# Frontend design

- Follow the user's request and the target project's existing components, tokens, icons and interactions. Read a nearby screen or its stylesheet before choosing a style.
- Put the task and its primary action first. Use spacing, alignment and subtle surface changes to group related content. Keep secondary controls and detail nearby, disclosing them when needed. Stack panes on narrow screens.
- Use short labels. Show status, errors and consequences where people act. Omit tutorials, slogans and captions that merely describe visible controls.
- Preserve keyboard focus and the user's reading position. Keep long code and tables inside their own region. Check the main interaction at a narrow width.

For an Achbit inline preview, read `achbit-documents` → `references/interactive-previews.md` with `skill.read` for delivery. For an existing app, work in its own source and build system.
