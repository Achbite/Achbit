这个面板不能作为现有 UI 插件实现

Achbit 的显示插件是 display-only 合同，槽位与输入都是封闭的。

types.ts:1
"Display-only API. Plugins receive no Session, Provider, tool or permission ports."
槽位
message.plain · message.markdown · document.html · document.markdown · document.pdf · theme
输入
UiPluginInput 只有 message 文本与 document Blob；没有用量、价格或额度
结论
既没有"统计面板"槽位，也没有数据端口。要承载这个面板，必须扩展公共 UI 合同，然后才谈实现。

数字从哪来：三类字段

1. 现已存在，直接用（标记「投影」）

  • TokenUsageProjection：providerCallCount、reportedCallCount、inputTokens、outputTokens、cacheReadInputTokens、cacheMissInputTokens、cacheAvailable、cacheComplete、cacheHitRatio
  • TokenUsageRoundProjection[]：按轮次的同一组字段，外加 runId / title / sequence / startedAt / completedAt / outcome —— 迷你趋势图直接来自这里
  • SessionProjection.modelSettings：当前模型与 profile，用于选择单价

cacheComplete / cacheAvailable 决定了缓存命中率是否可显示；两者为 false 时应显示"—"而不是 0%。

2. 需新增配置（标记「单价配置」）

  • 每个模型的 input / output / cache-read / cache-write 单价，以及币种
  • 单价表版本标识（价格会变，历史轮次必须按当时的价格算，否则总额会漂移）
  • 套餐定义：名称、额度口径（金额 / 请求数 / token）、窗口长度、上限、重置规则

3. 需新增事实（标记「需新增聚合」）

  • 跨会话的窗口消耗：5 小时窗口把其他会话也算在内，只统计当前会话会得到错误结论
  • 窗口归属：每次 provider 调用的时间戳落在哪个窗口，需要可重算
  • 额度重置事件：窗口滚动后的基线

价格与额度都不是 Kernel 的执行事实，也不是 Provider 返回的数据。这些数据的 owner 需要你决定。

三条落地路线（最小候选，待裁决）

A. 只做本会话成本，额度靠手工 Session 已在投影里提供 token 数；新增一张用户价格表（设置项），GUI 本地计算金额并显示在会话头部。额度由你手工填写"已用/上限"，产品不做跨会话聚合。
触碰层：UI + 用户设置。不动 Kernel、不动 Session 事实。代价：额度是静态数字，不会自动更新。
B. Session 拥有价格与额度事实 Session 在 reducer 里按调用时间戳把 token 数折算成金额，并把窗口占用作为新的投影字段（例如 planUsage）发布给所有外壳；窗口定义与单价来自用户设置。
触碰层：Session 投影 + 公共协议 + UI。代价：新增公共投影字段与 wire schema，需要先定语义（时间基准、重置边界、跨会话可见性）。
C. Host 侧独立账本 Host 监听会话事件，维护一个独立用量库并对外提供查询接口；UI 只读该接口，插件通过新槽位消费。
触碰层：Host + UI 合同扩展。风险：与规则"不得形成第二事实源"直接相关，需要明确 Host 账本只是派生视图、并且能从 Session journal 完整重建。

无论选哪条，面板槽位都需要一次公共 UI 合同扩展（新增槽位与对应 input 切片），这属于用户裁决范围，不是实现细节。

本预览的边界

  • 所有数字为示例值，但按真实字段口径构造，且总额与各明细自洽（$0.40 + $0.28 + $0.47 = $1.15；12 轮柱状图合计 $1.15）
  • 颜色、圆角、字号、字重、阴影取自当前安装的 Achbit 深色主题令牌；真实接入时会继承用户选择的主题与强调色
  • 单文件、无外部依赖、无网络请求；未修改任何产品代码、合同或配置
