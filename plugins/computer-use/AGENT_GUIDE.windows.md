## Desktop control (Windows)

`computer.control` uses UI Automation, window capture and Windows input. Windows has no per-app Accessibility or Screen Recording grant. Windows of elevated (administrator) apps reject observation and input from a normal session; that error is reported, not bypassed. `status` reports the executor process, integrity level and capabilities.

Identify the target with `listApps` / `listWindows`. `app` is the full executable path from `listApps`, such as `C:\Windows\System32\notepad.exe`, not the display name; packaged apps report their own executable rather than the frame host. For pixels only, `capture` takes exactly one `windowId` or `display=primary` and does not create an actionable observation. For interaction, `observe` requires `app`; an exact `windowId` defaults to background mode, which captures the window without activating or raising it. App-only observe uses the app's foreground window or its only window; with several windows, pass the exact `windowId`. Explicit `mode=foreground` brings that window to the front.

Every input action requires `app` and a fresh `observationId`. `press` needs an exact `elementId` and uses the element's Invoke, Toggle, Select, Expand/Collapse or default action; `setValue` needs `elementId` and `text` and replaces a Value control's text rather than typing. These actions do not move the cursor or fall back to mouse/keyboard events. `click`, `type`, `key`, `scroll` and `drag` require a foreground observation. Keys use `ctrl`, `alt`, `shift` and `win` modifiers; `cmd` is rejected. Scroll deltas are mouse wheel units (120 is one notch; positive `deltaY` scrolls up). Coordinates are pixels in the returned window screenshot. Actions use the observed process, window and run; a minimized, closed, moved or resized window requires another observation.
