## Desktop control (Windows)

`computer.control` uses UI Automation, window capture and Windows input. Windows has no per-app Accessibility or Screen Recording grant. Windows of elevated (administrator) apps reject observation and input from a normal session; that error is reported, not bypassed. `status` reports the executor process, integrity level and capabilities.

Identify the target with `listApps` / `listWindows`. `app` is the full executable path from `listApps`, such as `C:\Windows\System32\notepad.exe`, not the display name; packaged apps report their own executable rather than the frame host. For pixels only, `capture` takes exactly one `windowId` or `display=primary` and does not create an actionable observation. For interaction, `observe` requires `app`; an exact `windowId` defaults to background mode, which captures the window without activating or raising it. App-only observe uses the app's foreground window or its only window; with several windows, pass the exact `windowId`. Explicit `mode=foreground` brings that window to the front.

Every input action requires `app` and a fresh `observationId`. `press` needs an exact `elementId` and uses the element's Invoke, Toggle, Select, Expand/Collapse or default action; `setValue` needs `elementId` and `text` and replaces a Value control's text rather than typing. After setValue, a bounded read of the same retained control reports `valueVerification`. A mismatch or read failure preserves `dispatched=true` and an `actionError` (`computer_value_not_applied`); inspect the returned observation before deciding another action. These actions do not move the cursor or fall back to mouse/keyboard events. `click`, `type`, `key`, `scroll` and `drag` require a foreground observation. Keys use `ctrl`, `alt`, `shift` and `win` modifiers; `cmd` is rejected. Scroll deltas are mouse wheel units (120 is one notch; positive `deltaY` scrolls up). Coordinates are pixels in the returned window screenshot. Actions use the observed process, window and run; a minimized, closed, moved or resized window requires another observation.

For a Windows screenshot-and-mouse task, use `computer.control` throughout the desktop input sequence. Derive positions from its current screenshot or element bounds; these already use screenshot pixels, so do not apply desktop DPI or browser devicePixelRatio again. Chrome may initially expose only its window frame through UIA; use the screenshot and a subsequent observation instead of declaring page accessibility unavailable. Browser/CDP input is a separate control route and does not demonstrate Windows mouse or keyboard input.

Observations expire after 120 seconds, including time spent waiting for approval. A successful input returns the next observation; use that ID. On `Observation is stale`, observe the exact target again before deciding a new action. Permission approval does not refresh an image or prove that the window is unchanged. Keep the error and distinguish an action rejected before input from `dispatched=true` followed by an observation error.

Do not replace a failed or waiting plugin action with ad hoc global input. If the user explicitly requests a native Win32 experiment, verify the exact foreground HWND and target position before each input; stop immediately on failed focus or a mismatched position. Inspect the target's state before retrying. A missing page input event proves only that the target did not receive the intended input; it does not identify another recipient. Querying the foreground after an activating observe cannot reconstruct the earlier foreground.

For external Chrome verification, use an owned instance with a unique profile and temporary directory under the session workspace. Shell TEMP/TMP refer to invocation-scoped scratch and are cleaned when the command ends; a browser that outlives it needs task-scoped child TEMP/TMP as well as its profile. Use the existing host permission request for interactive browser launch and the required local debugging connection. Select an available debugging port and verify the exact page URL and owned instance before CDP commands. Preserve the PID and close only the instance created for this task.

PowerShell verification scripts must stop on errors (`$ErrorActionPreference = 'Stop'`) and check native command exit codes and expected results. Shell `success=true` alone does not establish that every command succeeded. `shell_cleanup_failed` can follow a successfully launched process: inspect its recorded execution result and live state before retrying, and resolve the owned process/directory lifetime. Use `${url}?…` when appending a query to a PowerShell variable. Empty `--dump-dom` output is a failure of that invocation to investigate, not evidence that Chrome removed the feature.

Keep acceptance evidence per control route. Record the initial state, actual action/count/text, resulting state and its screenshot immediately, before reload, reset or a different driver changes the page. CDP may read state to corroborate desktop input, but CDP mutations cannot satisfy desktop test cases. Present the archived image that matches the claimed result; count unperformed cases as unverified. WGC continuous preview, operation-position feedback and stop/release need their own observations, not merely a successful final screenshot.
