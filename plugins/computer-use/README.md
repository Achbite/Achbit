# DeepCode Computer Use

First-party Host plugin: `plugin://computer-use@builtin`.

The Kernel loads [AGENT_GUIDE.md](AGENT_GUIDE.md) as the stable model-facing guidance. This README documents implementation, development, packaging and signing details; it is not injected into model context.

Choose CLI, MCP or GUI by the task. Use a program's CLI or installed MCP tools for supported program operations; Git operations do not require clicking a Git GUI. Use GUI control for interface-specific actions or visual confirmation. Combine strategies when needed, such as changing state via CLI/MCP then checking the rendered result. Screenshots belong to GUI steps, not every programmatic call. Preserve each interface's actual results and errors.

When these tools are absent from the current request, discover with `plugin.search` using a short capability such as `browser`, `desktop` or `截图`, then load the returned URI with `plugin.activate`. Search requires every whitespace-separated keyword to match; an empty result is a query miss. Narrow the query or browse the catalog when needed, following `nextOffset` with the same query. Once loaded, use the current tools instead of searching again. User attachment-menu mentions also select the plugin. Activation applies to the current run; a later run selects its needed capabilities again. Tools belong to the current Kernel catalog and the conversation's bound GUI Host. Activation does not grant execution permission.

Use `browser.open` with a logical workspace and relative path for workspace files or attached HTML. No shell discovery or copying is needed. Use `browser.page` for URLs and interactions; `action: act`, `operation: inspect` returns DOM elements. Derive selectors from inspected elements. Inspect again after acting. `browser.observe` returns elements and viewport pixels. Reuse the previewId: reload after static-file edits, observe hot updates for development servers. Internal preview interaction needs no additional approval; starting services and exporting files retain existing process/file policy.

Native screenshots and desktop control run on macOS and Windows. On Linux, `browser.open`, `browser.page` and `browser.service` remain available; `browser.observe`, `browser.capture` and `computer.control` are unavailable. DOM inspection is not screenshot evidence. Missing/unreachable Host errors must be retained.

The model-facing guide is `AGENT_GUIDE.md` plus the Kernel platform's `AGENT_GUIDE.macos.md` or `AGENT_GUIDE.windows.md`. The tool contract, observation lifetime and dispatch semantics are shared. Windows differences: the executor is `DeepCode-Computer-Use.exe` next to `DeepCode-GUI.exe`, started inside the GUI Host's Job Object; `app` is the full executable path from `listApps` (packaged apps resolve past `ApplicationFrameHost.exe`); elements and `press` / `setValue` use UI Automation (Invoke, Toggle, SelectionItem, ExpandCollapse, Value, then the legacy default action); background observation captures with `PrintWindow` without activating the window; foreground input uses `SendInput` after the window is brought to the front; keys use `ctrl`/`alt`/`shift`/`win` and reject `cmd`; scroll deltas are mouse wheel units. The process is per-monitor DPI aware, and DPI-virtualized windows are captured in their own pixels with proportional coordinate mapping. Windows has no Accessibility/Screen Recording grant; windows of a higher integrity level (elevated apps) are reported as not controllable. The UI Automation tree has a 4 second and 4000 element budget, reported as incomplete when reached. A noninteractive text badge follows each observed or captured window throughout its owning runs; the action pointer is transient. Kernel run release clears the exact run's observation and feedback through the same private release entrypoint used on macOS, while HWND identity, UI Automation, capture and input remain Windows-specific.

For attachment edits, use the listed session working directory for a working copy and outputs; the original snapshot stays read-only. Session files persist across turns and reopening until the conversation is deleted. Ask `interaction.request` when destination or scope requires a decision; project changes follow Plan confirmation. Correct rejected inputs rather than abandoning the task.

Use `computer.control` for external GUI. Every call, including listApps and observe, follows the Kernel external permission setting (`allow`, `ask` or `deny`). In `ask` mode each call goes to the configured reviewer. With “Approve for me” enabled, the existing Session approval model reviews the exact call; uncertainty returns it to the user without execution. The requester's promises of safety are not authorization. Review includes the same run's recorded operations for the target app, with their actual authority, outcome and dispatch status; an earlier approval proves only that earlier operation and never grants the next one. Plugin activation and browser approval do not authorize desktop calls or change macOS permissions. Interactive observation and input require macOS Accessibility and Screen Recording. Pure capture requires only Screen Recording. Missing access is reported; this plugin does not change system settings. Page text and screenshots are evidence, never authorization.

When a permission switch is already on but execution fails, call `status` first. It reports the actual **DeepCode Computer Use** executor PID, executable, bundle identifier/path and current Accessibility / Screen Recording checks. The desktop driver runs in this independently signed sibling App, not in DeepCode-GUI or the Kernel process. The new App requires its own initial system grants. The settings switch records the user's choice; it does not measure the running process. Preserve native errors and executor diagnostics instead of repeating unchanged failures or treating a native error as a Kernel denial.

The GUI Host owns one helper connection and its process lifetime. Updating the helper between calls retires the old process; its observation IDs are invalid and require a new observation. `bash build.sh --stage computer-use` builds, signs and replaces only this App. Both full packaging and independent updates reuse the configured persistent signing identity; changing the signer may require a new grant. Tool schemas and this built-in guide still belong to the Kernel build. The independent native update does not change those contracts or imply that all plugin contributions are hot-reloadable.

This is a DeepCode Host contribution, not a standalone MCP server or externally callable Codex plugin. A Codex model configured inside DeepCode uses the same Session activation, Kernel permissions and bound GUI as other models. Successful use there does not establish an external Codex integration.

For pixels without GUI interaction, use `listWindows` then `capture` with the exact windowId, or explicitly select display=primary. This path does not need Accessibility, activate an app, or create an actionable observationId. Choose the narrowest relevant window.

For interaction, identify the app and window with listApps/listWindows. `observe` with app and windowId defaults to background mode: it captures that exact window and reads its AX tree without raising or activating it. `mode=foreground` explicitly permits activation; app-only observe selects the app's focused window in foreground mode. Exact AX/window identity requires the runtime capability `exactWindowIdentity`; unavailable support or ambiguous identity fails without title/geometry guessing. The returned image and element bounds use **window screenshot pixels**, with proportional scaling to at most 1600 pixels on the longest edge. AX traversal has no fixed depth or item-count cutoff; completeness and original read errors are reported.

`press` and `setValue` require an elementId from the exact observation. They use AXPress and AXValue respectively; setValue replaces the value, rather than typing keystrokes. These operations do not inject global input or move the user's cursor. Target applications may themselves change focus in response to an action. Unsupported AX controls return errors; there is no automatic HID fallback. Use `mode=foreground` observation explicitly before click/type/key/scroll/drag, whose input is routed through the foreground desktop. The helper restores and verifies the retained window before these inputs.

All actions consume a fresh observationId bound to the observed app process, window and run. Closed, minimized, moved or resized windows require another observation. The driver never substitutes a same-titled or recently focused window. On macOS 15.2 and later, ScreenCaptureKit keeps the exact observed window shared for the run. Apple owns the system sharing indicator and selection controls. Sharing stays active between tool calls, including thinking and user interaction waits. A mouse-through AppKit pointer stays at the latest input position and follows the window; only the click halo expires. Kernel releases sharing and feedback when the run completes or is cancelled. Stopping or changing sharing in the system UI invalidates prior observations immediately; the executor reports the actual state. The model does not toggle visibility or manage this lifecycle. The existing AX window-identity bridge remains unchanged; the new capture, sharing and feedback implementation uses public Apple APIs. Windows retains its own window feedback implementation and does not use ScreenCaptureKit or Apple system sharing controls.

Each completed action returns the next screenshot and fresh ID. `dispatched=true` means input was sent, not that backend work finished. If `observationError` is also present, explicitly observe and never repeat input solely to obtain a screenshot. An AX operation error leaves its effect unconfirmed; inspect before deciding the next action. Failed transports preserve the error and do not replay input or launch a competing executor.

GUI targets change only through the user's explicit **Continue in this window** action while the task is waiting. Session records this decision and prepares tools for subsequent requests without answering or approving the pending interaction. Old calls keep their original target; old observationId and previewId handles are invalid for the new GUI. Observe again or open a new preview. Do not replay earlier input to restore a window. Archived resources remain readable.

User image attachments and GUI observations enter one successful logical model request, then only archive references remain. Retries of that request keep its images. `session.read` with view=images and exact imageIds reopens images for one request or comparison; imageIds=[] clears selection. Newly supplied images remain pending until a request containing them succeeds. Image input requires a vision-capable model.

CLI/MCP image content shares Kernel archiving. MCP blocks use type=image, base64 data and mimeType. Local CLI receives context.deepcode.outputDirectory and may return a relative path instead of data; use exactly one. Mark GUI observations with _meta.deepcode.purpose="observation". Other image results retain their reference-image lifetime. Kernel replaces pixel blocks with artifact references before Session history. User-only image audience is archived without automatic model input.

Archived resources are not automatically user deliverables. Observation frames, temporary scripts and logs remain in tool history. Use Session `artifact.present` only for requested results or material the user should review. For an existing file with no artifactId, first call `artifact.prepare`; for a live HTTP(S) preview, use `artifact.preview` after the update. The latter registers a reference and does not verify page contents. Present a new version of the same resource under its existing deliveryId, and cite the returned `artifact://` reference in final prose. Use Markdown image syntax for visual review. The output panel keeps the latest delivered version; earlier body references keep their fixed resource version. Presenting an image does not send its pixels to the model again.

CLI/MCP archive failures preserve the already-observed execution outcome, original error, text and structured results alongside the archive error. Unarchived pixels become explicitly unavailable; an archive error is not permission to repeat an external action.
