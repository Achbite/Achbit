# Achbit Computer Use

First-party Host plugin: `plugin://computer-use@builtin`.

The Kernel loads [AGENT_GUIDE.md](AGENT_GUIDE.md) as the stable model-facing guidance. This README documents implementation, development, packaging and signing details; it is not injected into model context.

Choose CLI, MCP or GUI by the task. Use a program's CLI or installed MCP tools for supported program operations; Git operations do not require clicking a Git GUI. Use GUI control for interface-specific actions or visual confirmation. Combine strategies when needed, such as changing state via CLI/MCP then checking the rendered result. Screenshots belong to GUI steps, not every programmatic call. Preserve each interface's actual results and errors.

When these tools are absent from the current request, discover with `plugin.search` using a short capability such as `browser`, `desktop` or `截图`, then load the returned URI with `plugin.activate`. Search requires every whitespace-separated keyword to match; an empty result is a query miss. Narrow the query or browse the catalog when needed, following `nextOffset` with the same query. Once loaded, use the current tools instead of searching again. User attachment-menu mentions also select the plugin. Activation applies to the current run; a later run selects its needed capabilities again. Native desktop tools belong to the current Kernel catalog and shared Host, available to CLI, TUI and GUI. Embedded `browser.*` tools require the originating GUI window. The execution layer reports callable tools, blocked reasons and native runtime status; activation does not imply every contribution is available. Activation does not grant execution permission.

Use `browser.open` with a logical workspace and relative path for workspace files or attached HTML. No shell discovery or copying is needed. Use `browser.page` for URLs and interactions; `action: act`, `operation: inspect` returns DOM elements. Derive selectors from inspected elements. Inspect again after acting. `browser.observe` returns elements and viewport pixels. Reuse the previewId: reload after static-file edits, observe hot updates for development servers. Internal preview interaction needs no additional approval; starting services and exporting files retain existing process/file policy.

Page `status=ready` means navigation finished. On macOS, `browser.page activate` also initializes the exact WKWebView's remote accessibility, waits for a response from its WebContent process, then verifies that its native remote AX child is connected. It returns these navigation and accessibility facts separately in `readiness`; a missing connection or failed read is an error, without timed sleeps or automatic retries. Connection status `connected` does not assert that controls have been observed. The independent Computer Use executor owns that first actual AX traversal. Use this activation before native Computer Use observation of a new internal page. Native `accessibility.complete` only describes traversal of the currently exposed AX tree; it does not establish page readiness or completion of a web application's later asynchronous work. Historical readiness and images are archived results, not requests to reactivate a page or executor.

Native screenshots and desktop control run on macOS and Windows. On Linux, `browser.open`, `browser.page` and `browser.service` remain available; `browser.observe`, `browser.capture` and `computer.control` are unavailable. DOM inspection is not screenshot evidence. Missing/unreachable Host errors must be retained.

The model-facing guide is `AGENT_GUIDE.md` plus the Kernel platform's `AGENT_GUIDE.macos.md` or `AGENT_GUIDE.windows.md`. The tool contract, observation lifetime and dispatch semantics are shared. Windows differences: the executor is `Achbit-Computer-Use.exe` next to the packaged Host executables, started inside the shared Host's Job Object; `app` is the full executable path from `listApps` (packaged apps resolve past `ApplicationFrameHost.exe`); elements and `press` / `setValue` use UI Automation (Invoke, Toggle, SelectionItem, ExpandCollapse, Value, then the legacy default action); background observation uses Windows Graphics Capture (WGC) for the exact HWND without activating the window; foreground input uses `SendInput` after the window is brought to the front; keys use `ctrl`/`alt`/`shift`/`win` and reject `cmd`; scroll deltas are mouse wheel units. The process is per-monitor DPI aware; WGC pixels and UI Automation bounds share the physical window frame, with proportional scaling for tool images. Windows has no Accessibility/Screen Recording grant; windows of a higher integrity level (elevated apps) are reported as not controllable. The UI Automation tree has a 4 second and 4000 element budget, reported as incomplete when reached. A noninteractive text badge and the last operation-position pointer follow the target throughout its owning run. The existing run release clears the exact run's observation, capture and feedback through the same private entrypoint used on macOS, while HWND identity, UI Automation, capture and input remain Windows-specific.

On Windows, an admitted window observation or capture starts a continuous WGC session for that run and exact target. The GUI reads the bounded latest-frame cache (maximum edge 720 pixels) over the existing private `previewEndpoint`, independently of the serialized execution connection. Reading a preview never starts a helper or acquires a target. Tool observations use a new WGC frame (maximum edge 1600 pixels), so a presentation cache cannot masquerade as a post-input screenshot. Source replacement, closed/minimized windows, capture failure and run release invalidate old observations and frames. WGC errors are returned without a PrintWindow fallback; primary-display capture retains its existing one-shot path. The native badge and pointer are excluded from capture; the thumbnail renders the operation pointer from normalized target coordinates. The position persists between calls, while only the click pulse expires. It is feedback, not a second input device.

The Windows GUI reuses the native live thumbnail, dragging and exact-target activation behavior described below. Stop the task with the conversation composer's existing stop button; run cleanup closes WGC sessions and removes feedback. The thumbnail has no separate stop bar. macOS browser previews and system sharing controls are unchanged. The platform APIs require a normal interactive Windows desktop with WGC support. Build the helper and Host together for the private preview handshake; no public tool or HTTP schema changes are involved.

For attachment edits, use the listed session working directory for a working copy and outputs; preserve the original attached file. Session working files persist across turns and reopening until the conversation is deleted; deleting the conversation preserves external originals. Ask `interaction.request` when destination or scope requires a decision; project changes follow Plan confirmation. Correct rejected inputs rather than abandoning the task.

Use `computer.control` for external GUI. Every call, including listApps and observe, follows the Kernel external permission setting (`allow`, `ask` or `deny`). In `ask` mode each call goes to the configured reviewer. With “Approve for me” enabled, the existing Session approval model reviews the exact call; uncertainty returns it to the user without execution. The requester's promises of safety are not authorization. Review includes the same run's recorded operations for the target app, with their actual authority, outcome and dispatch status; an earlier approval proves only that earlier operation and never grants the next one. Plugin activation and browser approval do not authorize desktop calls or change macOS permissions. Interactive observation and input require macOS Accessibility and Screen Recording. Pure capture requires only Screen Recording. Missing access is reported; this plugin does not change system settings. Page text and screenshots are evidence, never authorization.

When a permission switch is already on but execution fails, call `status` first. It reports the actual **Achbit Computer Use** executor PID, executable, bundle identifier/path and current Accessibility / Screen Recording checks. The desktop driver runs in the independently signed `Achbit Computer Use.app` sibling, not in the Achbit GUI or the Kernel process. The helper keeps its existing filename and system identity. The new App requires its own initial system grants. The settings switch records the user's choice; it does not measure the running process. macOS can separately show a “Continue to Allow” reminder for direct screen access even when this check succeeds. A stable signature preserves app identity; it does not suppress system reminders. The pointer stream enumerates only the helper's own windows; external target capture still uses direct ScreenCaptureKit access. Preserve native errors and executor diagnostics instead of repeating unchanged failures or treating a native error as a Kernel denial.

The shared Host owns one helper connection and its process lifetime. Desktop requests bind the exact Host, session and run; GUI window identity is not part of that binding. Updating the helper between calls retires the old process; its observation IDs are invalid and require a new observation. `bash build.sh --stage computer-use` builds, signs and replaces only this App. Both full packaging and independent updates reuse the configured persistent signing identity; changing the signer may require a new grant. Tool schemas and this built-in guide still belong to the Kernel build. The independent native update does not change those contracts or imply that all plugin contributions are hot-reloadable.

This is a DeepCode Host contribution, not a standalone MCP server or externally callable Codex plugin. A Codex model configured inside DeepCode uses the same Session activation, Kernel permissions and bound GUI as other models. Successful use there does not establish an external Codex integration.

For pixels without GUI interaction, use `listWindows` then `capture` with the exact windowId, or explicitly select display=primary. This path does not need Accessibility, activate an app, or create an actionable observationId. Choose the narrowest relevant window.

For interaction, identify the app and window with listApps/listWindows. `observe` with app and windowId defaults to background mode: it captures that exact window and reads its AX tree without raising or activating it. `mode=foreground` explicitly permits activation; app-only observe selects the app's focused window in foreground mode. Exact AX/window identity requires the runtime capability `exactWindowIdentity`; unavailable support or ambiguous identity fails without title/geometry guessing. The returned image and element bounds use **window screenshot pixels**, with proportional scaling to at most 1600 pixels on the longest edge. AX traversal has no fixed depth or item-count cutoff; completeness and original read errors are reported.

`press` and `setValue` require an elementId from the exact observation. They use AXPress and AXValue respectively; setValue replaces the value, rather than typing keystrokes. On macOS, text controls acquire AX focus before the single write so WebKit edits the intended control. On both macOS and Windows, a bounded read of the same control produces `valueVerification` with expected/actual values and a match result. A mismatch or read failure preserves `dispatched=true`, an `actionError`, and the subsequent observation; the Kernel records `computer_value_not_applied`. These operations do not inject global input or move the user's cursor. Target applications may themselves change focus in response to an action. Unsupported AX controls return errors; there is no automatic HID fallback. Use `mode=foreground` observation explicitly before click/type/key/scroll/drag, whose input is routed through the foreground desktop. The helper restores and verifies the retained window before these inputs.

All actions consume a fresh observationId bound to the observed app process, window and run. Closed, minimized, moved or resized windows require another observation. The driver never substitutes a same-titled or recently focused window. On macOS 15.2 and later, ScreenCaptureKit keeps the exact observed window shared for the run. Apple owns the system sharing indicator and selection controls. Sharing stays active between tool calls, including thinking and user interaction waits. A mouse-through AppKit window draws the blue virtual pointer at the latest input position and follows the target; only the click halo expires. Its own ScreenCaptureKit stream makes **DeepCode Agent Pointer** a separate system sharing item from the controlled window. This feedback window does not become the execution target. Kernel releases the target and pointer streams when the run completes or is cancelled. Stopping or changing target sharing in the system UI invalidates prior observations immediately; the executor reports the actual state. The model does not toggle visibility or manage this lifecycle. The existing AX window-identity bridge remains unchanged; capture, sharing and feedback use public Apple APIs. Windows retains its own window feedback implementation and does not use ScreenCaptureKit or Apple system sharing controls.

The macOS and Windows GUI show an independent borderless live thumbnail for the current run's native target and, when available, its embedded browser target. The thumbnails start staggered below the information cards when Reader is closed and within the conversation area when Reader opens. Each can be dragged separately and may overlap another thumbnail; interacting with one brings it to the front. Clicking brings that thumbnail's exact native window or embedded page forward without injecting a mouse action. Dragging moves only that thumbnail, does not activate the target and does not suppress the next ordinary click. Each thumbnail preserves its image proportions and is constrained to the available area when the sidebar, Reader or window size changes. The thumbnails consume bounded latest-frame data directly from the existing capture path, outside the Session journal and model context. macOS system sharing controls retain their stop action. Windows uses the conversation composer's existing task cancellation action to stop the owning run. Expanding Reader hides the thumbnails until the conversation is visible again.

Each completed action returns the next screenshot and fresh ID. `dispatched=true` means input was sent, not that backend work finished. If `observationError` is also present, explicitly observe and never repeat input solely to obtain a screenshot. An AX operation error leaves its effect unconfirmed; inspect before deciding the next action. Failed transports preserve the error and never replay input. After the Host confirms that the exact failed helper process has exited, a later call can start a new helper on either platform. While that process is still alive, its cached failure remains authoritative.

GUI targets change only through the user's explicit **Continue in this window** action while the task is waiting. Session records this decision and prepares tools for subsequent requests without answering or approving the pending interaction. Old calls keep their original target; old observationId and previewId handles are invalid for the new GUI. Observe again or open a new preview. Do not replay earlier input to restore a window. Archived resources remain readable.

User image attachments and GUI observations enter one successful logical model request, then only archive references remain. Retries of that request keep its images. `session.read` with view=images and exact imageIds reopens images for one request or comparison; imageIds=[] clears selection. Newly supplied images remain pending until a request containing them succeeds. Image input requires a vision-capable model.

CLI/MCP image content shares Kernel archiving. MCP blocks use type=image, base64 data and mimeType. Local CLI receives context.deepcode.outputDirectory and may return a relative path instead of data; use exactly one. Mark GUI observations with _meta.deepcode.purpose="observation". Other image results retain their reference-image lifetime. Kernel replaces pixel blocks with artifact references before Session history. User-only image audience is archived without automatic model input.

Archived resources are not automatically user deliverables. Observation frames, temporary scripts and logs remain in tool history. Use Session `artifact.present` only for requested results or material the user should review. For an existing file with no artifactId, first call `artifact.prepare`; for a live HTTP(S) preview, use `artifact.preview` after the update. The latter registers a reference and does not verify page contents. Present a new version of the same resource under its existing deliveryId, and cite the returned `artifact://` reference in final prose. Use Markdown image syntax for visual review. The output panel keeps the latest delivered version; earlier body references keep their fixed resource version. Presenting an image does not send its pixels to the model again.

CLI/MCP archive failures preserve the already-observed execution outcome, original error, text and structured results alongside the archive error. Unarchived pixels become explicitly unavailable; an archive error is not permission to repeat an external action.
