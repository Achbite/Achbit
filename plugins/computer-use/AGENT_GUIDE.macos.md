## Desktop control (macOS)

Native screenshots and `computer.control` require macOS 15.2 or later. On older supported macOS versions, desktop activation reports this requirement before launching the helper; chat, file tools and browser tools remain available. Observation and input require Accessibility and Screen Recording; pure capture needs only Screen Recording. Missing access is reported, not changed by the tool. `status` reports the actual executor permissions.

Identify the target with `listApps` / `listWindows`. `app` is the exact bundle identifier, such as `com.google.Chrome`, not the display name. For pixels only, `capture` takes exactly one `windowId` or `display=primary` and does not create an actionable observation. For interaction, `observe` requires `app`; `observe` defaults to background mode, with or without a `windowId`. App-only observe selects the app’s focused window without activating it. Prefer an exact `windowId` with background observation for reading and supported AX actions. Explicit `mode=foreground` permits focus restoration when the task needs mouse/keyboard input. The observation returned after an action does not activate the app again; later mouse/keyboard input still restores and verifies the retained window.

Every input action requires `app` and a fresh `observationId`. `press` also needs an exact `elementId` whose observed actions include `AXPress`; an `AXWindow` that only offers `AXRaise` is not a press target; `setValue` needs `elementId` and `text` and replaces the AX value rather than typing. These AX actions do not inject global input or fall back to mouse/keyboard events. `click`, `type`, `key`, `scroll` and `drag` require a foreground observation and their action-specific fields. Coordinates are pixels in the returned window screenshot. Actions use the observed app process, window and run; changed or ambiguous targets require another observation.

An observed window remains shared throughout the run, including gaps between actions. The blue virtual pointer has its own **Achbit Agent Pointer** system sharing item; it is feedback, not a different control target. The system sharing UI owns selection and stop; stopping or changing the target selection invalidates previous observations. `status` reports this state. Run completion or cancellation releases target sharing and pointer feedback automatically. The GUI thumbnail only displays and reveals the current target; clicking it is not an input action to that target.
