## Desktop control (macOS)

Native screenshots and `computer.control` require macOS 15.2 or later. On older supported macOS versions, desktop activation reports this requirement before launching the helper; chat, file tools and browser tools remain available. Default AX observation and semantic input need Accessibility, not Screen Recording. Window discovery reads available metadata without capturing. Direct capture and explicit pixel observations need Screen Recording, not an AX tree. Input always requires Accessibility. Missing access is reported, not changed by the tool. `status` reports the actual executor permissions.

Identify the target with `listApps` / `listWindows`. `app` is the exact bundle identifier, such as `com.google.Chrome`, not the display name. For pixels only, `capture` takes exactly one `windowId` or `display=primary` and does not create an actionable observation. For interaction, `observe` requires `app`; `observe` defaults to background mode, with or without a `windowId`. App-only observe selects the app’s focused window without activating it. Prefer an exact `windowId` with background observation for reading and supported AX actions. Explicit `mode=foreground` permits focus restoration when the task needs mouse/keyboard input. The observation returned after an action does not activate the app again; later mouse/keyboard input still restores and verifies the retained window.

Every input action requires `app` and the current `observationId` from this executor/run, valid for at most 120 seconds. Do not repeat `windowId` on input: the observation already binds it. If a package update replaces the executor, observe the exact window again; do not replay a previous input. Another run's active sharing must be released by its owner before switching executors. `press` also needs an exact `elementId` whose observed actions include `AXPress`; an `AXWindow` that only offers `AXRaise` is not a press target; `setValue` needs `elementId` and `text` and replaces the AX value rather than typing. These AX actions do not inject global input or fall back to mouse/keyboard events. `click`, `type`, `key`, `scroll` and `drag` require a foreground observation and their action-specific fields. `boundsWindowPoints` and `centerWindowPoints` are logical points from the whole window’s top left (including its title bar). Use `coordinateSpace:"windowPoints"` for click/drag on a no-image observation. Request `includeScreenshot:true` on observe only when you need the AX tree and an image, or `observationType:"pixels"` for the exact window without AX. Only a real image permits `imagePixels` or legacy unmarked pixel coordinates. Post-action observation preserves this choice. Actions use the observed app process, window and run; changed or ambiguous targets require another observation.

A failed native call can return `diagnostics.observationView.truncated`. Its error is still a failure; the inline AX errors are samples. Use `diagnostics.observationView.diagnosticCounts` for totals and read `diagnostics.observationView.fullOutput.path` in bounded chunks under normal file permissions for the original failure. An `archiveError` means the full detail is unavailable; do not repeat input to recreate it. A control with `enabled:false` was disabled when observed, even if it listed `AXPress`.

A pure AX observation does not share the window or produce a PNG/model image. Explicit visual observations reuse the exact window’s target stream within this run; the tool PNG is not the GUI thumbnail. If more recent visual evidence is unavailable after dispatch, inspect `observationError` and do not retry the input. The blue pointer is local feedback, not a separate sharing item. The system sharing UI owns selection and stop; stopping or changing the target selection invalidates previous observations. `status` reports this state. Run completion or cancellation releases target sharing and pointer feedback automatically. The GUI thumbnail only displays and reveals the current target; clicking it is not an input action to that target.
